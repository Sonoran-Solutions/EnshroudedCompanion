# ShroudForge diagnostic bootstrap review artifact — NOT_INSTALLABLE

This is a separate build of the pinned, guard-patched ShroudForge Windows bootstrap for parent review. It is not deployed and is not a production execution profile. Existing runtime/profile/asset/UI/Rust paths are untouched. New source files are owned only by this probe directory. The existing bootstrap owns process identity/startup gating, the existing entry fixture owns adapter emission, and the existing telemetry fixture owns bounded publication. This probe composes those implementations without copying their policies into a new framework.

Run `timeout 120 probes/p0-shroudforge-diagnostic/build-review.sh`. It uses the existing isolated toolchain, no installed packages. Output lives under `/tmp/enshrouded-p0-toolchain/diagnostic-review/`; the DLL is named `winmm-diagnostic-NOT_INSTALLABLE.dll`. The script records source commit, hashes of all included upstream headers/forwarder source, fixture headers, probe sources and build script, compiler/linker/Wine versions, DLL SHA256, PE imports/exports and fixture results. No game executable is read or started by the build/test script. Wine tests use a fresh private `/tmp/p0-diagnostic-refusal.XXXXXX` prefix that is stopped and removed on exit.

## Files and execution flow

- `diagnostic_bootstrap.cpp` replaces the normal bootstrap DllMain/worker for this artifact only. It directly includes the unchanged guarded `verify_bootstrap_image.h`, `sha256_digest.h` and `startup_gate.h` from the pinned source checkout. A supported process name must be the client. Full protected-file SHA/length and loaded PE identity checks precede StartupGate installation. Attach failure cancels the gate and closes private events/protected-file handles. The worker requires StartupGate's entered event before preparing the observation adapter. Failure completes the gate unsuccessfully; only complete hook initialization releases it successfully.
- `prepare_entry_adapter.c` compiles the existing `entry_adapter.h` as C, avoiding a modified emitter or C++ language-extension dependency. It allocates a bounded near-code candidate, builds the strict supported entry shape, changes the generated page from RW to RX, flushes the cache, and registers its unwind table before returning a publication candidate. Unregistered private failures release the allocation. Once registered, its table and code stay allocated until process exit even if later publication refuses.
- `test_admission_and_publication.cpp` is a separate synthetic EXE including the same internal admission/publication helpers. It does not add runtime guard overrides or a test export to the DLL.
- `refusal_host.cpp` checks that an unrelated synthetic process leaves startup inert. The same synthetic host named `enshrouded.exe` must be refused at DllMain before a gate or worker exists.

The protected on-disk handle remains open without write/delete sharing. Only after full image verification does the worker map it read-only, derive 64 guarded bytes at the typed actor-entry RVA, verify the first 11 bytes against their separately pinned digest and require signed LEA displacement -200. The reused emitter validates the exact supported RBP/RBX/LEA instruction shape. Loaded-header/section metadata is read with bounded `ReadProcessMemory` copies and must equal the SHA-verified disk metadata. Loaded executable sections must have exactly one match, at the typed RVA. This uniqueness is rechecked after preparing the adapter. All 64 guarded bytes, including the original continuation, are rechecked again under the thread suspension guard immediately before publication. No game bytes or proprietary disassembly are stored in this repository.

The patch helper retains the reviewed source writer's prepare-handles-before-suspend behavior and refuses thread enumeration, opening, suspension, context or occupied-RIP failures. It makes one attempt. The target page is temporarily RW, with other enumerated threads suspended, then returned to its previous executable protection. Cache flush and protection restoration are checked; ambiguous post-write failure or failure to resume a suspended thread terminates the process rather than releasing StartupGate. There is no retry, unpatch or unload path. The unchanged upstream StartupGate itself retains its existing temporary RWX entrypoint-patch implementation; this probe does not claim to have replaced or tested that policy.

The worker pins its own module before preparing code. Observation is `noexcept` and captures only raw incoming RCX plus `GetCurrentThreadId()` through the existing lock-free, bounded 8192-slot buffer. After one-way disable is observed it returns before calling the thread-ID API. It does not dereference RCX, resolve owners, query ECS, dispatch actions, allocate, log or perform external I/O. The callback target, table, code and storage remain for process lifetime. Disable is one-way and permits already-started captures to finish. The worker records at most 120 approximately one-second bounded samples after publication, then disables capture. Each sample contains elapsed milliseconds, reserved/dropped/published counts and a count of distinct thread IDs among published slots. IDs and raw pointers stay in memory. A final snapshot 100 ms after disable permits comparison with the last pre-disable snapshot, but pending captures may finish and this delay does not prove quiescence. The JSON explicitly says `quiescenceProven:false`. Distinct-thread coverage is limited to captured slots and stops expanding after buffer saturation. The worker then attempts a unique `CREATE_NEW` count-only JSON summary beside the DLL. It never overwrites existing logs/configuration and exports no raw pointers. Worker scheduling can delay disable; this is not a hard real-time deadline. No summary is written during the build/refusal/synthetic helper checks.

The 180 original ordinal/name/system32 winmm forwarders are generated directly from the original source pragmas, preserving their absolute target and ordinal. Only `ShroudforgeDiagnosticStatus` and `ShroudforgeDiagnosticDisable` are additional exports. Status values are 0 attaching/inert, 1 parked, 2 installed, 3 disabled, 4 refused. No arbitrary action API exists. The static runtime link imports only KERNEL32.dll and msvcrt.dll.

## Executed checks and remaining blockers

The final cross-build passes with warnings treated as errors. PE validation checks all 180 exact forwarders, exactly 182 export names, the two typed diagnostic exports and the system-only import set. Private Wine checks pass: unrelated host exit 0, named wrong-image refusal exit 66. The separate helper EXE passes missing/duplicate loaded-site refusal, loaded metadata mismatch, expected-byte and changed-continuation mismatch without target change, occupied-RIP refusal without target change, preservation of a pre-existing thread suspend count, successful synthetic target publication/execution through the actual reused adapter, one-way disable, retained registered unwind storage after disable, a count-only sample of the published observations, and unchanged reservation count during synthetic calls after disable. An owned suspended fixture thread is restored to its original context and allowed to exit normally; it is not killed. Synthetic target/code allocations deliberately remain until fixture process exit.

This is still **NOT_INSTALLABLE** pending independent review. No positive game-image process admission, actual callback cadence/session identity, native Windows, real exception dispatch, DLL pin/unload behavior, comprehensive failure injection (VirtualProtect/cache-flush/RtlAdd/resume failures), thread-creation races during enumeration, or game runtime path has been exercised. The shared entry fixture's separate 301 virtual-unwind boundary checks remain relevant but do not prove raised-exception behavior. The synthetic PE helper fixture is not a game compatibility result. No game prefix, save, world, production profile or game file was changed. No commit.

## Separate positive synthetic composition

`test-composition.sh` adds a second private-prefix check. It compiles `composition_host.cpp` and `composition_entry.S`, whose own function has the accepted stack-only shape and returns 7. A private temporary copy of the same diagnostic source and strict identity header changes only compile-time host SHA/PE/file-length/site-RVA/entry-digest constants. There is no runtime bypass in either DLL. StartupGate/SHA headers and adapter object remain the same. `composition-transform.json` records exact unified source/header differences and original/transformed hashes; `composition-input-hashes.txt` and `composition-artifacts.sha256` bind its sources and temporary synthetic binaries. Temporary modified headers/sources/DLL/host are removed afterward.

The positive composition passes: main enters with status 2, ten calls traverse the installed shared adapter and original remainder, disable changes status to 3, the original remainder still returns 7, and a unique count-only summary records ten reserved captures. The unchanged production diagnostic DLL then refuses this exact same synthetic host with exit 66, and its binary hash must remain unchanged. This validates synthetic composition and early disable/summary behavior only. It does not admit the actual game image or establish sustained cadence, concurrency, real exception behavior or quiescence. `composition-result.txt` contains the observed result.

## Real-duration synthetic expiry check

`composition_host.cpp --wait-expiry` performs ten captures and waits without calling the disable export. `test-composition.sh` runs this mode with a 135-second process timeout after the manual-disable check, under a 210-second whole-job cap. Each host reads only its own PID-specific summary pattern, preventing reuse of the manual run's summary. The unchanged production DLL is tested for refusal afterward, and its SHA256 must remain unchanged.

Observed expiry pass: host measured **120014 ms** until automatic disabled status, and the worker's post-disable snapshot measured **120111 ms**. All **120** bounded samples and the post-disable snapshot reported ten reserved/published captures, no drops and one captured thread. The original continuation still returned 7 after automatic disable. The manual-disable and expiry count-only summaries are retained as `composition-manual-summary.json` and `composition-expiry-summary.json`; transformation/source/binary hashes were refreshed for these exact runs. Both summaries retain `quiescenceProven:false` and `pendingCapturesMayFinish:true`. This tests the real-duration automatic-disable path in the synthetic composition; it does not establish live game cadence, concurrency or quiescence.
