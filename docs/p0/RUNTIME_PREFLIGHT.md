## Definite source blockers

The unmodified stock loader cannot be described as an exact-build, all-required-symbol fail-closed load-only probe:

1. [`DllMain`](https://github.com/bonsaibauer/shroudforge/blob/3ed90de1df266c4f0c217523a02a71dfa67243de/modules/entrypoints/windows-bootstrap/startup.cpp) checks executable name and immediately calls `StartupGate::Install`. [`Install`](https://github.com/bonsaibauer/shroudforge/blob/3ed90de1df266c4f0c217523a02a71dfa67243de/modules/entrypoints/windows-bootstrap/startup_gate.h) validates AMD64 PE shape, image bounds and entrypoint, then overwrites 14 entrypoint bytes with a temporary jump using `VirtualProtect`. This happens before the native-provider profile/hash check. It saves/restores original entrypoint bytes and blocks startup until completion; it has no exact game hash allowlist. Even a nominal load-only launch changes executable memory and is not a passive read-only experiment.
2. [`run`](https://github.com/bonsaibauer/shroudforge/blob/3ed90de1df266c4f0c217523a02a71dfa67243de/modules/entrypoints/windows-bootstrap/runtime_lifecycle.cpp) runs an update check, loads `shroudforge-runtime.dll`, verifies its four exports, starts UI, and invokes `shroudforge_prepare_startup` (asset preparation/baseline recovery) before native provider initialization. Thus the full package is not inherently a no-asset-write probe. Native initialization failure merely logs a warning and startup is released. Missing primary runtime DLL/exports or failed asset preparation does block startup, which is a different guarantee.
3. [`EcsRuntime::Initialize`](https://github.com/bonsaibauer/shroudforge/blob/3ed90de1df266c4f0c217523a02a71dfa67243de/modules/game-runtime/native/ecs/bind_world_entities.cpp) stores the result of profile `Load()`, calls `EngineHooks::Install()` only if that result is true, **does not propagate the hook-install result**, and returns true after basic PE checks even when no execution profile exists. Its comment explicitly retains metadata discovery without proven execution adapters. Therefore a positive initializer return is not proof that required symbols/hooks resolved.
4. [`Load`](https://github.com/bonsaibauer/shroudforge/blob/3ed90de1df266c4f0c217523a02a71dfa67243de/modules/game-runtime/native/profiles/select_game_profile.cpp) prefers exact profiles, but allows manual selection or `allowStructuralRevalidation` fallback. Merely setting `runtime.profileId` is not a strict mode: manual selection explicitly qualifies a nonmatching profile for fallback. [`ReadGameProfile`](https://github.com/bonsaibauer/shroudforge/blob/3ed90de1df266c4f0c217523a02a71dfa67243de/modules/game-runtime/native/profiles/read_game_profile.cpp) allows some guarded operations on differing builds (`build-diff-guard-verified`). Do not remove profiles or falsify identity/provenance to claim strict refusal.
5. [`install_hook` / `EngineHooks::Install`](https://github.com/bonsaibauer/shroudforge/blob/3ed90de1df266c4f0c217523a02a71dfa67243de/modules/game-runtime/native/engine-hooks/install_engine_hooks.cpp) genuinely requires a unique executable signature and exact overwritten instructions; code-write attempts revalidate originals. Missing game-thread/entity-manager hooks uninstall installed hooks and return false. Optional prop/placement/building-dispatch/cursor hook failures disable their availability while other hooks continue. These are meaningful per-feature safeguards, but not global loader refusal. `supported_image` checks loaded timestamp/image size against the identified image state; it does not change the fallback policy into a pinned-build allowlist.

Additional safeguards remain valuable: [`runtime_bridge.cpp`](https://github.com/bonsaibauer/shroudforge/blob/3ed90de1df266c4f0c217523a02a71dfa67243de/modules/entrypoints/windows-bootstrap/runtime_bridge.cpp) checks provider ABI and required exports before initialization; exact owner-layout configuration independently checks SHA256/timestamp/image size. None repairs the earlier ordering/global-refusal issues above. No supported strict/no-hooks startup configuration was established in the reviewed startup path and default config. Disabling mods or UI does not skip native bootstrap.
