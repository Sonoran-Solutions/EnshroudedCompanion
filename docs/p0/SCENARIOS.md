These are proposed per-session limits, not constraints on preparation, source review, or the overall investigation. The full matrix will not fit one session: run the smallest prerequisite slice and record omitted rows as `NOT_RUN`; do not rush destructive or multi-step cases to fit. Any additional session must remain within the ratified P0 budget. Stop sooner on a stop condition in [validation](../VALIDATION_AND_OPERATIONS.md) or [handoff](../PHASE_0_HANDOFF.md). Only the designated live integrator may write to the test world.

Before the clock starts, stage the already-authorized clients, logs, scenario checklist, disposable-world backup and restore instructions. Do not count preparation as test evidence. Record the repository/code SHA, loader revision, game and server revisions/fingerprints, OS/compatibility layer, topology, world/profile identity, client identities, start/end time, and operator. If prerequisites are absent, do not start the live session; retain `NOT_RUN` with the missing prerequisite.

For each row, evidence means timestamped, correlated observation/event/action/result records where the candidate bridge exposes them, plus a short screen recording or screenshots when useful. Capture identifiers and provenance without publishing private saves, account data, secrets, or game binaries. If the candidate surface cannot expose evidence sufficient to establish an assertion, record `HOLD` with the reason; do not substitute a visual impression or fixture for runtime proof.
